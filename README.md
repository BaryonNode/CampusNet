# <img src="icon.png" width="40" valign="middle" alt=""> CampusNet · 校园网自动认证

不打开浏览器、不点击任何按钮，用纯 HTTP 请求完成校园网认证。

> ### ⚠️ 使用前请确认符合你所在学校的网络使用规定
>
> 本工具只是把**你手动点击的认证流程自动化**，使用的是**你自己的账号**和**你自己的设备**：
> 它完成的是认证，不是绕过认证；不共享账号、不干扰计费、不攻击系统。
> 但**部分学校的网络使用条款可能不允许脚本认证**，请先自行确认，风险自负。

> **适合谁**：使用「统一身份认证（金智 LinkID）+ 门户网关（eportal / InterFace.do）」的校园网。
> 认证服务器地址与网关地址由程序**自动识别**，你只需要填账号和密码。

```
双击 run.bat  →  填账号密码  →  完事
```

---

## 特性

- **零交互认证**：不启动浏览器，不模拟点击，几百毫秒完成
- **自动识别**：认证域名、门户网关地址由程序自己探出来，不需要你查任何 IP
- **双击即用**：没有配置时弹图形向导；已配置时静默运行，连窗口都没有
- **联网即认证**：可选注册计划任务，绑定系统「网络链路建立」事件，**进程零常驻**
- **凭据加密**：密码用 Windows DPAPI 加密存储，密文拷到别的机器上也解不开
- **绝不自欺**：成功与否只认真实外网探测结果，不看任何"认证成功"提示
- **失败不盲重**：账号密码类错误立即停止，避免连错触发验证码或锁定账号
- **断网可回滚**：如果为了认证切换了无线却失败，会自动切回原来的网络

## 快速开始

### 方式一：直接运行源码

```bat
pip install -r requirements.txt
run.bat
```

没有配置时会弹出向导：

```
┌────────────────────────────────────────┐
│  账号（学号/工号）  [_______________]   │
│  密码               [_______________]   │
│  校园网             [ CampusWiFi  ▼ ]   │
│                                        │
│  认证服务器  [ 自动探测后自动填写 ]      │
│  门户网关    [ 自动探测后自动填写 ]      │
│                                        │
│  [自动探测并保存] [保存] [立即测试连接]  │
│  [开机自动认证]                         │
└────────────────────────────────────────┘
```

填好账号密码、选一下校园网，点「自动探测并保存」即可。

### 方式二：命令行（可选，排障用）

```bat
python connect.py --check         :: 当前是否已联网
python connect.py --wlan-scan     :: 列出可见无线网络
python connect.py --detect        :: 只自动识别认证服务器与网关
python connect.py --dry-run -v    :: 演练全流程，不真正提交
python connect.py --selftest      :: 离线自检（不联网、不需要账号）
```

## 开机/联网自动认证

在向导里点「开机自动认证」，或在命令行：

```bat
python connect.py --task install     :: 注册
python connect.py --task status      :: 查看
python connect.py --task uninstall   :: 移除
```

原理：绑定系统日志 `Microsoft-Windows-NetworkProfile/Operational` 的
**Event ID 10000**（网络链路建立）。平时程序完全不运行，CPU 和内存占用为 0；
只有网卡状态变化的那一瞬间才会被拉起。

## 工作原理

| 层 | 文件 | 做什么 |
|---|---|---|
| L0 | `campusnet/wlan.py` | 无线关联（`netsh`），等待地址与路由稳定 |
| L1 | `campusnet/portal.py` | 触发探测、捕获门户跳转，**自动识别认证域名与网关** |
| L2 | `campusnet/cas.py` | 统一身份认证登录，拿到 `ticket` |
| L3 | `campusnet/eportal.py` | 门户网关认证（运营商/服务选择走 cookie） |
| L4 | `campusnet/verify.py` | 真实外网探测（内容比对 + HTTPS 复核） |
| L5 | `campusnet/runner.py` | 编排、重试、失败回滚 |

几个关键点：

- **自动识别怎么做到的**：未认证时任何 HTTP 请求都会被网关劫持并跳转，
  跳转目标的主机名就是认证域名，`service=` 参数就是门户网关地址。两个都从跳转链里解析出来。
- **一次性令牌**：`wlanuserip / wlanacname / nasip / mac / url` 是网关加密下发、
  必须原样回传的令牌，无法自行构造，因此每次运行都会重新获取。
- **代理**：所有请求都设了 `trust_env=False`，系统里的代理残留不会影响认证。
- **成功判定**：只有探针内容符合预期 **且** 外部 HTTPS 站点可达，才算成功。

## 配置文件

`config.json`（已加入 `.gitignore`，不会进版本库）：

```json
{
  "username": "20230001",
  "password_enc": "<DPAPI 密文>",
  "ssid": "CampusWiFi",
  "cas_base": "https://sso.example.edu.cn",
  "eportal_base": "http://192.0.2.10",
  "service": "移动互联网服务",
  "max_retries": 3
}
```

- `password_enc` 是 Windows DPAPI 密文：**换机器或换用户都解不开**，拷走文件也没用
- `cas_base` / `eportal_base` 留空时会在首次认证时自动识别并回填
- `service` 是运营商/服务名。**很多学校的网关同时提供校园网 + 三大运营商，
  必须指定一个**，否则会报 `服务不能为空`。默认 `移动互联网服务`，
  在向导的下拉框里可随时更改；`--services` 可尝试自动列出网关提供的服务

## 排障

| 现象 | 处理 |
|---|---|
| 双击没反应 | 先 `pip install -r requirements.txt`；或看 `logs/campusnet.log` |
| 提示"尚未完成配置" | 运行一次向导（双击 `run.bat`） |
| **提示"服务不能为空"** | 网关同时提供校园网和多家运营商，必须选对。在向导下拉框里换一个（默认 `移动互联网服务`），或 `python connect.py --services` 看列表 |
| 自动识别失败 | 确认已连上校园网**且当前还没认证**；否则手动填认证域名与网关 |
| 提示需要图形验证码 | 通常是密码连错多次导致，先在浏览器里正常登录一次即可清除 |
| 认证成功但浏览器打不开网页 | 系统代理残留，关掉代理软件或在配置里打开 `clear_system_proxy` |
| 想确认到底做了什么 | 用 `--dry-run -v` 演练一遍，日志会脱敏输出每一步 |

日志在 `logs/campusnet.log`，账号与密码会被自动打码。
